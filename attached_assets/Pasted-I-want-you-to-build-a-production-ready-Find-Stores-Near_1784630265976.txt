9. STORE RANKING SYSTEM — VERY IMPORTANT
==================================================

Implement a ranking system for store discovery.

The ranking must work in:

A. All Stores
B. Individual Store Categories

The ranking should prioritize stores based on the ADMIN'S PLAN VALUE.

The ranking must NOT simply sort by distance.

PLAN + DURATION BASED RANKING:

We have:
- Plan
- Plan price
- Plan duration

First calculate the equivalent 30-day value of the plan.

Formula:

30-Day Plan Value =
(Total Plan Price / Plan Duration in Days) × 30

Normalize all plans to a 30-day value.

Example:

Plan A:
Price = ₹999
Duration = 30 days

30-Day Value =
999 / 30 × 30
= ₹999

Plan B:
Price = ₹5,999
Duration = 365 days

30-Day Value =
5999 / 365 × 30

Plan C:
Price = ₹15,999
Duration = Lifetime

For Lifetime plans, inspect the existing SaaS business logic and determine the appropriate lifetime duration/value already used in the project.

DO NOT invent a completely separate lifetime pricing system.

If the existing project does not have lifetime normalization logic, create a configurable system where Super Admin can define the lifetime normalization period.

The ranking should compare normalized 30-day plan values.

Higher 30-day plan value = Higher ranking.

Lower 30-day plan value = Lower ranking.

Example:

Store A:
30-day plan value = ₹999

Store B:
30-day plan value = ₹493

Store A should rank above Store B.

The ranking should be applied:

1. In All Stores
2. Inside every individual category

For example, if the user selects Clothing:

Clothing stores should be ranked based on their normalized 30-day plan value.

If the user selects All Stores:

All eligible stores should be ranked based on their normalized 30-day plan value.
